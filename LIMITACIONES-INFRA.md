# Infraestructura: contrato y limitaciones

- El backend se ejecuta como `app:app` desde `/app/backend` y sirve `/app/frontend/dist`. El puerto publicado está limitado a `127.0.0.1`; no se configura TLS ni autenticación.
- `DATABASE_PATH=/data/status.db` es fijo en Compose y compartido por el backend, backup y restore; `/data` es persistente. Variables: `PORT`, `NETDATA_URL`, `NETDATA_TOKEN` opcional, `NETDATA_CHARTS`, `POLL_INTERVAL_SECONDS`, `HISTORY_RETENTION_DAYS` y `TZ`. El primer `install.sh` crea `.env` privado y continúa; no sobrescribe una configuración existente.
- El valor predeterminado `NETDATA_URL` apunta a `host.docker.internal`; Netdata debe escuchar en una interfaz accesible desde Docker. Si solo escucha en loopback del host, no será accesible por esa dirección. No se modifican Netdata ni el firewall. El healthcheck solo verifica el proceso API, no Netdata ni métricas del anfitrión.
- `backup.sh` usa SQLite Online Backup, incluyendo transacciones confirmadas en WAL; requiere servicio activo y guarda una copia privada en `backups/`. `restore.sh --confirm archivo` valida la copia, crea otro backup y detiene servicios antes de sustituir el contenido SQLite; si falla tras parar, quedan detenidos. Proteja y pruebe copias fuera del host. No incluye otros archivos ni secretos.
- `update.sh` requiere backup previo y no descarga código; reconstruye desde el directorio actual y verifica API y frontend, sin rollback automático si falla. `uninstall.sh --confirm` elimina contenedores y red del proyecto, conservando volúmenes y backups. Los comandos requieren acceso local al daemon; la aplicación no monta el socket.
- El preflight requiere Linux, Docker/Compose accesible, Python 3 y puerto loopback libre o ya ocupado por el servicio de este proyecto. Comprueba el puerto en el host local: no es válido para un daemon remoto y existe una carrera entre comprobación y publicación. No se eliminan automáticamente contenedores huérfanos de versiones anteriores.
- En el PC amd64 se construyó y arrancó la imagen, se comprobó `healthy`, se ejecutó el instalador dos veces y se verificó una copia SQLite. Restore y ARM64 siguen sin comprobar. Existe `frontend/package-lock.json`; el frontend se compiló y probó en navegador con Netdata simulado, pero la compatibilidad con Netdata real sigue pendiente.
